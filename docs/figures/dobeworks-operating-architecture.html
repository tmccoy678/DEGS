DobeWorks

Useful work. Evidence you can inspect. A clear explanation when something needs attention.

Figure 1
The current staged components and their separate responsibilities

1. Define the work

State the outcome, scope, risk, acceptance criteria, and responsible decision maker.

2. Evaluate the record

DEGS checks the recorded controls and returns a readiness decision with rule-linked findings.

3. Run a bounded task

The synthetic Worker verifies identity and limits, then writes staged output. It does not promote it.

4. Inspect and decide

The Observer reports permitted signals and explicit unknowns. A person decides whether results are acceptable.

What is present now

The drafts contain the standalone evidence gate, source and policy documents, a synthetic Worker and Observer, and runnable examples. They preserve the core behavior while making its decisions easier to inspect.

What requires a separate decision

A recorded PASS does not approve work. Staged output does not become accepted output by being written. Tests do not qualify hardware or establish operating effectiveness.

Reading the figure. The numbered sequence explains responsibility. It is not an automatically connected execution pipeline. Each component has an explicit interface and limits.

Evidence has a boundary

The strength of the explanation should match the strength of the observation.

The gate evaluates records

A structured task record enters DEGS. Source code does not run inside the gate. The evaluator checks schema, declared risk and authority, required controls, warnings, and stop states. Its output names unmet fields and stable rule IDs.

Figure 2
From an engineering claim to an inspectable readiness result

1. Record

Objective, requirements, risk, artifact identity, tests, review, recovery, and approval evidence.

2. Check

Schema and supported rules; cumulative requirements for the declared risk tier.

3. Report

PASS, PASS_WITH_WARNINGS, BLOCKED, or FAIL, plus actionable diagnostics.

Human judgment remains necessary

The gate can inspect a recorded status or evidence path without proving the underlying evidence true, independent, complete, or technically sound. Reviewers still judge consequential evidence (Hirshorn et al., 2017; Souppaya et al., 2022).

What the current evidence supports

Observed scenarios are useful evidence. They are not a promise of defect freedom.

DEGS: a useful failure is still a result

The corrected public schema-helper subset matched 241 of 241 examples; 74 core/port tests and five benchmark tests pass. The first run matched 227; its 14 false acceptances traced to one nested boolean/number comparison defect. That observation is preserved. No bypass of the current fixed task schema was demonstrated.

DobeWorks: controlled handling of unusable input

The actual Observer command-line interface (CLI) produced controlled, unusable outcomes for 318 out-of-contract public JSON inputs. Its native fresh and stale examples behaved as expected in the measured run. The repaired harness retains timeout diagnostics, requires stale freshness, and records actual invocation arguments. Six benchmark tests pass.

Current qualification limits

The recorded Worker/Observer suite passed 70 tests. Historical DobeWorks Engineering Assurance Standard (DEAS), Phase 3, and Phase 4 package checks also have inherited identity/scope failures in the draft baseline. The drafts remain private, unqualified development copies. Apple silicon is the tested host scope; other platforms are not claimed.

Credit where it belongs

The foundations span systems engineering, secure development, modular design, verification, and human responsibility. Intended full-bundle composition - packaging remains to be verified

A separate gift for Pickup-only users

The standalone Draft2Staged Trash/Treasure pair serves people who want those context-transfer skills without DobeWorks/DEGS. It is not a substitute dependency for the full system's integrated workflows.

Preserve the useful core

Release preparation should remove personal identifiers while keeping core behavior, source structure, and FigureMe's explanatory character as close to the originals as possible. This diagram records intended composition; it does not claim the current drafts already package every component.
